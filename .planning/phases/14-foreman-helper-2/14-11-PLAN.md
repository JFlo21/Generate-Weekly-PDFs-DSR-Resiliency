<objective>
Close O-14-C: rows frozen before they carried a Helper #2 currently keep `frozen_helper2` NULL
forever, because the deployed `freeze_attribution` is first-write-wins per ROW (`ON CONFLICT DO
NOTHING`) and the pipeline never re-sends an already-frozen row. Give Helper #2 — and only Helper #2 —
first-write-wins per ROLE: the function fills the two Helper #2 columns on conflict when they are still
empty, the pipeline re-sends an already-frozen row only when it now carries a valid Helper #2 and the
prefetched snapshot says the role is still empty, and the fill is counted and traceable.

Purpose: 14-09 shipped Helper #2's attribution columns, but the read-back on 2026-09-08 (D-14-07-VERIFIED,
deviation (c)) showed the "adjacency" edge assumption of that plan was false in production: an existing
row does NOT gain Helper #2 values. Without this plan, 14-10's rollout would promise attribution that
only newly frozen rows ever get, and a foreman added to a row after its first freeze would never be
credited in the audit snapshot.

Output: a Python admission rule plus counter (TDD), one owner-approved SQL file with a contract test,
and an owner-gated apply with a read-back that proves the fill on a synthetic row.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
