<objective>
Prove the whole Helper #2 path end-to-end on the thinnest possible slice: ONE ordinary
(non-subcontractor, non-VAC) source row with a valid Helper #2 completion travels discovery →
field extraction → eligibility → grouping → change-detection identity → workbook → filename →
filename round-trip, behind a default-off flag, and comes out the far end naming the same person
at every hop.

Purpose: this is the tracer. Every later Phase 14 plan expands horizontally from a path that is
already proven, so an architectural dead-end costs one commit instead of ten. The slice is
production-quality, not a prototype: it carries the D-14-05 fabricated-claim guard, the
Pattern-B subcontractor guard, and real regression coverage from day one.

Output: a working `helper2` variant (plain, non-shadow) behind `HELPER2_ENABLED`, a new
Helper #2 test module, a family-parity invariant test, and byte-identity regression cases proving
the legacy identities did not move.

This plan also fixes the phase-wide token vocabulary that D-14-11 leaves to the planner — the
variant strings, filename tokens, row-metadata keys, flag name, and log reason codes in
`<vocabulary_lock>` below — so every later plan inherits one spelling instead of re-deriving it. And
it implements D-14-09: Helper #2 fields enter a hash, a key, or a filename ONLY under a Helper #2
variant, never as empty fields appended to a primary, Helper #1, or VAC identity.

**Scope decision — Task 1 stays one task (recorded 2026-09-05, plan revision).** Task 1 touches eight
production modules and the estimate puts this plan at 84k against a 100k smart-zone budget with low
confidence. It is deliberately NOT split. The only seam available is a horizontal one —
discovery/fetch/grouping in one task, change_detection/orchestrate/excel in another — and either half
alone proves nothing end-to-end, which is precisely the failure a tracer exists to prevent. Splitting
here would convert the tracer into two layer tasks and move the architectural risk from commit one to
commit two. The eight files are touched thinly: one variant string, one capability gate, one metadata
key set, one group-key infix, one hash meta token, one filename token, in one path each. If the
executor exceeds budget mid-task, the correct response is to stop after the slice is committed and
report it, not to widen the slice.
</objective>
