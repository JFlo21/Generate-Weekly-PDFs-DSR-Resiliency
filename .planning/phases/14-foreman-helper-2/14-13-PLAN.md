<objective>
Close O-14-E: the `helper2-v1` mapping-schema marker is never written in production because neither
`upsert_sheet_registry` call site in `pipeline/orchestrate.py` passes `mapping_schema_by_sheet`, so the
D-11.1-01 registry-version skip is defeated on every run (121 full validations, ~38 s, observed on run
`34356004448`).

Purpose: restore the D-14-10 design — one full validation per sheet, then cache admission — without
weakening the Phase 11 rule that a frequent run never silently adopts a drifted mapping.

Output: a discovery-side getter for the skip-admitted ids, a pure orchestrate helper that derives the
marker set, the two call-site kwargs, and tests that pin the caller (not only the writer).
</objective>

<context>
@.planning/phases/14-foreman-helper-2/14-DECISIONS.md — read `D-14-10-APPLIED`, `O-14-E`.
@.planning/phases/14-foreman-helper-2/14-07-SUMMARY.md — the writer contract this plan wires.

Marker semantics chosen here: marker = fully validated this run ∩ column_mapping written this call.
On a frequent run `_compute_registry_mapping_sheets` returns only NEW sheet ids, so an already-registered
sheet keeps echoing its stored mapping and earns the marker on the next `weekly_comprehensive` (Monday
05:00Z) deep run, when every mapping is refreshed. New sheets earn it on their first run.
</context>
