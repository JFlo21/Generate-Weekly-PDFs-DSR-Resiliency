<objective>
Turn a working, flag-off feature into something an operator can switch on, watch, compare, and turn
back off — and rehearse that path in escalating order before anything reaches a live sheet.

Purpose: every prior plan in this phase produced fixture evidence. Fixture evidence is not a dry run,
and a dry run is not an upload. This plan is where those become separate, labelled claims, where the
rollback is written down before it is needed, and where the one genuinely irreversible step — a real
attachment on a real sheet — is put to the owner as its own decision.

Output: the runbook page and the three other places the flag must be documented, a rehearsed pilot
with stated comparison criteria, a documented rollback, and the owner's recorded decisions on flag
default, workflow wiring, and the single controlled upload.
</objective>

## The four evidence labels, used unmerged

Fixture pass means a test suite passed. Dry-run pass means the pipeline ran without producing a live
attachment — and the plan states, per command, what that run still did. Controlled upload verified
means one real attachment was created on a real sheet and compared. Production observed means a
scheduled run produced the expected result. This plan produces the first two, may produce the third
only with the Task 3 authorization, and cannot produce the fourth.
