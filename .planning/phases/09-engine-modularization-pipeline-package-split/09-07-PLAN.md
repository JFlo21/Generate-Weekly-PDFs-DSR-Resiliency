<objective>
Close gap **G-09-MOD-06**: make Gate 4 of the Phase-09 6-gate harness actually
capable of reporting FAIL, and pin that capability with tests so it cannot
silently regress again.

Today `scripts/check_mypy_delta.sh` is structurally unable to fail. The frozen
baseline `tests/golden/mypy_baseline_count.txt` checks out as `56\r\n` on this
`core.autocrlf=true` clone; the script's count read deletes spaces and LF but
not CR, so the value becomes `56<CR>`; the `-gt` comparison then raises a bash
test-syntax error (exit status 2) *inside an `if` condition*, which `set -e`
explicitly does not abort on; execution falls through to the unconditional
`echo "PASS: ..."` / `exit 0` at the bottom of the file. Reproduced live during
the 2026-08-24 retroactive verification: the gate printed PASS while the real
mypy count had gone 56 -> 65.

Purpose: MOD-06 claims "the 6-gate harness is green at every step." A gate that
cannot fail is not green — it is unmeasured. This plan restores the measurement.

Output: a CRLF-immune, fall-through-proof Gate 4; LF-pinned golden baselines;
four new fail/pass-capability tests in the existing harness test file; and a
Living Ledger entry recording the two standing rules the incident produced.

**Explicitly OUT of scope for this plan:** any change to `pipeline/*` or
`generate_weekly_pdfs.py` to clear the real 56 -> 65 mypy delta, and any
re-baselining of `tests/golden/mypy_baseline*.txt` *values*. This plan changes
line endings only. Attribution and the fix-vs-re-baseline decision are plan
`09-08`.
</objective>
