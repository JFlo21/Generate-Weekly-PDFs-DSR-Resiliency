<objective>
Second half of gap **G-09-MOD-06**. Plan `09-07` restored Gate 4's ability to
fail. This plan deals with the two consequences of that:

1. **Gate 6 must stop reading production.** `scripts/run_6_gates.sh` runs
   `TEST_MODE=true SKIP_UPLOAD=true python generate_weekly_pdfs.py`. Per
   `pipeline/orchestrate.py`, `TEST_MODE` only selects the synthetic in-memory
   dataset when `API_TOKEN` is falsy. With a token present — which is the
   normal state on a developer machine with a `.env` — the same command does a
   FULL real read of all ~118 production Smartsheet source sheets. That is what
   pulled 208,511 rows and stalled the 2026-08-24 verification for 13+ minutes
   before Gate 6 was ever reached. A verification harness must not be a
   production data consumer.

2. **The real mypy delta must be attributed, not swallowed and not silently
   erased.** With Gate 4 fixed, the harness now reports the true `56 -> 65`
   regression. This plan identifies exactly which findings are new, which
   commit and phase introduced each, and presents Juan with an evidence-backed
   decision — it does NOT fix types and does NOT re-baseline.

Purpose: make MOD-06's "gates green at every step" a claim that can be
evaluated cheaply, deterministically, and offline.

Output: a one-line Gate-6 pin, a captured mypy artifact, a per-finding
attribution report with a decision list, and Juan's decision.

**Explicitly OUT of scope:** any change to `pipeline/*` or
`generate_weekly_pdfs.py` to clear the delta; any edit to
`.github/workflows/*`; any Smartsheet write; any Supabase change; any change to
the frozen baseline VALUES before Juan decides.
