## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Stacked PR orphaned by squash-merge | #352 was stacked on `feat/phase-11-incremental-read`; squash-merging #351 deleted that branch and GitHub auto-closed #352 as CONFLICTING. | advisory | Cut follow-up PRs from `master`; if stacking is unavoidable, rebase the top commit onto `origin/master` (`git rebase --onto origin/master <old-parent> <branch>`) and open a fresh PR immediately after the base merges. |
| `git rebase` refused by an unstaged runtime artifact | `generated_docs/hash_history.json` is always dirty (owner's runtime file); rebase aborted silently inside a `set -e` chain and a PR was opened from the un-rebased branch (49 files instead of 2). | advisory | Park the artifact (`cp` to scratch + `git checkout -- <file>`) before any rebase, restore after; check `git status --porcelain \| grep -v '^??'` is empty first. Never `git stash`. |
| Operator SQL written from memory | Runbook + checklist item 6 referenced `run_ledger.sheets_errored`, which does not exist (the count is `notes->>'mem_sheets_errored'`). | advisory | Verify column names against `information_schema.columns` (or `_RUN_LEDGER_FINISH_COLUMNS` in `pipeline_memory/writer.py`) before writing SQL into docs. Corrected in PR #355. |
| Fail-open empty result read as "nothing changed" | `upsert_rows_bulk` returned the same empty set for no-client / disabled / all-chunks-failed / partial as for a genuine no-change run; the incremental path would have regenerated nothing (Greptile P1, fixed `66ce083`). | advisory | Any writer whose empty result is ambiguous must return a status; scope-narrowing callers act only on a confirmed status (`UPSERT_CONFIRMED_STATUSES`, `memory_confirmed`). |
| Executor spawned for a `blocking-human` first task | An executor whose first task is `gate="blocking-human"` can only bounce the gate back; spawning it wastes a subagent. | advisory | Present the gate from the plan text with orchestrator-verified evidence; spawn the continuation executor only after the owner answers. |
