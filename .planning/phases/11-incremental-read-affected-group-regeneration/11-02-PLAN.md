## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Smartsheet API → pipeline | Untrusted response shapes (abbreviated vs full `Sheet` objects, 401/403 errors) cross into the fetch layer. |
| `pipeline_memory` (Supabase) → run-mode decision | Stored watermarks and the previous run's status now influence how much of the source data the run reads — memory becomes an input to a billing-adjacent decision for the first time. |
| Python process → Supabase `service_role` client | New SELECT queries cross this boundary using the existing service-role key. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-11-06 | Tampering | Watermark integrity (`sheet_registry.last_read_at`) | critical | mitigate | Task 3: persist the capture-time instant and subtract `SAFETY_WINDOW_MINUTES` only when building the filter. | T-11-07 | Denial of service (self-inflicted, on billing data) | Delta-read failure misread as "unchanged" | critical | mitigate | Tasks 1-2: every read failure, version-less abbreviated response, empty watermark map, or unexpected exception resolves to a full read. Fail-open toward MORE work is the only permitted direction. |
| T-11-08 | Tampering | Stale `sheet_registry.column_mapping` | high | mitigate | Task 2 trigger 2: dict-equality drift check forces a per-sheet full read; the run never groups against a stale mapping (misgrouping is a billing-integrity defect). |

| T-11-10 | Information disclosure | Smartsheet API token in retry/Sentry paths | medium | mitigate | The delta read goes through the existing `smartsheet_call_with_retry` wrapper and the existing `op="smartsheet.api"` span; no new logging of request headers or credentials is introduced. |
