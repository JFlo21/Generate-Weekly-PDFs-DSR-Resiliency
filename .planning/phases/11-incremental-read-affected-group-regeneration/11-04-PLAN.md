<objective>
Ship INC-02 as CONTEXT.md D-04's Option C: `row_state` decides membership, a scoped full
re-fetch supplies content, and the generation pipeline is unmodified. This is the plan
that actually makes the frequent run read less: PHASE 2 splits into a delta read (2a) and
a scoped full re-fetch (2b), with the affected-set mapping between them.

Purpose: grouping is cross-sheet — `group_source_rows` keys on Work Request, week,
variant, foreman, dept and job regardless of source sheet — so a delta read of only the
sheet that changed would starve a group of its other sheets' rows. The mapping step is
what makes a scoped read safe: it widens from "the changed rows" to "every sheet holding
any row for an affected (WR, week) pair", then re-fetches those sheets in full.

Output: `map_affected_to_sheets` in the reader, the PHASE 2a/2b restructuring, the
affected-pair restriction on `groups`, and the D-05 deferral recorded in REQUIREMENTS.md.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Smartsheet cell content → Supabase query construction | Work Request and week-ending values originate in operator-edited Smartsheet cells and now flow into a `pipeline_memory` query predicate. |
| `pipeline_memory.row_state` → regeneration scope | Stored membership decides which sheets are re-fetched and which groups regenerate. A wrong or narrow answer silently omits billing output. |
| Scoped `all_rows` → the unmodified generation pipeline | The generation pipeline trusts that its input row set is complete for every group it is asked to build. |

| T-11-18 | Denial of service (silent billing omission) | Narrowed regeneration scope from a partial or failed mapping | critical | mitigate | Tasks 1-2: a partial chunk union is discarded; an empty mapping means "cannot confirm" and resolves the run to full mode with a `fallback_reason`. The scope can only ever be too wide, never too narrow. |
