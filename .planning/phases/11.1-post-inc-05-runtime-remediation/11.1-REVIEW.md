## Critical Issues

### CR-01: Sentinel-identifier leading-underscore heuristic can misclassify a real name and delete a legitimate billing attachment

**File:** `pipeline/cleanup.py:89-116` (predicate), used at `pipeline/cleanup.py:495-508` (sentinel-superseded gate)

**Issue:**

`_is_sentinel_identifier` treats ANY sanitized filename identifier that
starts with `_` as a sentinel placeholder:

```python
if identifier.startswith('_'):
    return True
```

The comment justifying this states "A real person's sanitized name never
starts with `_`." That premise is false. The filename identifier is produced
by `_RE_SANITIZE_HELPER_NAME.sub('_', raw_name)` (`[^\w\-]` → `_`), which
replaces **any** non-word, non-hyphen character — including a leading space,
parenthesis, apostrophe, or other punctuation — with `_`. A raw Smartsheet
foreman/helper name with a leading space (a common, plausible data-entry
artifact — copy/paste noise, autocomplete, accidental keystroke) sanitizes to
a token that starts with `_` (e.g. `" Pat Example"` → `"_Pat_Example"`), and
is therefore misclassified as a sentinel by this heuristic even though it is
a genuine person's name.

This feeds directly into the sentinel-superseded cleanup gate
(`pipeline/cleanup.py:495-508`), which deletes an attachment when: its own
identifier is (mis)classified as sentinel, its identity is not produced this
run, and a **different**, non-sentinel identifier exists for the same
`(wr, week, variant)` and is live/attached this run. Concretely: if a helper
role transitions from "` Pat Example`" (leading-space typo, historically
uploaded as `..._Helper__Pat_Example_....xlsx`) to a genuinely different
person "`Sam Sample`" in a later run, the gate will treat Pat Example's file
as a stale placeholder superseded by Sam Sample's real name and delete it —
even though Pat Example is a real, distinct person whose historical billing
record is not a placeholder at all. This is a false-premise deletion in a
protected billing path (`CLAUDE.md` / `.claude/rules/billing-pipeline-
guardrails.md` both call out attachment-cleanup and the identity dimension
as guarded). No test in `tests/test_sentinel_superseded_cleanup.py` exercises
a real name with a leading special character, so this gap ships uncaught.

**Fix:**

Narrow the leading-underscore fast path so it only matches the shape of a
sanitized Smartsheet `#`-error token (which is the only case the surrounding
comment actually intends to catch), not any name that happens to sanitize to
a leading underscore:

```python
import re

# Sanitized Smartsheet '#' error tokens (#REF!, #INVALID, #NO MATCH, ...)
# render as a leading underscore followed by an all-caps/underscore run
# with no lowercase letters. A real person's sanitized name almost always
# contains lowercase letters, so require the whole token to look like an
# error code before treating a leading underscore as sentinel evidence.
_RE_SANITIZED_ERROR_TOKEN = re.compile(r'^_[A-Z0-9_]+$')

def _is_sentinel_identifier(identifier: str | None) -> bool:
    if not identifier:
        return False
    if identifier.startswith('_') and _RE_SANITIZED_ERROR_TOKEN.match(identifier):
        return True
    try:
        from billing_audit.writer import is_sentinel_claimer  # noqa: PLC0415
    except Exception:
        return False
    return bool(is_sentinel_claimer(identifier))
```

Add a regression test asserting `_is_sentinel_identifier('_Pat_Example')` is
`False` while `_is_sentinel_identifier('_NO_MATCH')` / `_is_sentinel_identifier('_REF_')`
/ `_is_sentinel_identifier('_INVALID')` remain `True`, plus an end-to-end
`test_sentinel_superseded_cleanup.py` case proving a leading-space real name
is never deleted when a differently-named real person supersedes the role.

## Warnings

### WR-01: New top-level SDK submodule import breaks this codebase's established defensive-import convention

**File:** `pipeline/orchestrate.py:39-43`

**Issue:**

```python
from smartsheet.models.enums.attachment_parent_type import (
    AttachmentParentType,
)
```

is added at **module import time**, at the top of `pipeline/orchestrate.py`
— the main production entry point. Every other deep `smartsheet.models.*`
submodule import in this codebase is deliberately lazy/scoped inside a
`try`/`with` block precisely so a Smartsheet SDK internal-module-path change
degrades gracefully instead of taking down the whole module load, e.g.
`pipeline/discovery.py:82-83`:

```python
try:
    with sentry_sdk.start_span(...):
        from smartsheet.models.sheet import Sheet as _SmartsheetSheet
        from smartsheet.models.folder import Folder as _SmartsheetFolder
```

`_is_row_attachment`'s own docstring explicitly frames the SDK-shape risk as
something that should "fail-safe" by degrading to "not a row attachment" —
but that fallback can only run if the import itself succeeds. If a future
`smartsheet-python-sdk` bump ever relocates or renames
`smartsheet.models.enums.attachment_parent_type` (an internal path, not part
of the SDK's public top-level `smartsheet` namespace), `pipeline/orchestrate.py`
will fail to import at all, which crashes the entire billing pipeline at
startup rather than the intended narrow, graceful degradation the new code
was designed around. Today's risk is low because `requirements.txt` pins
`smartsheet-python-sdk==4.3.0` exactly, but the inconsistency with the
codebase's own established pattern is a real robustness regression, not a
style nit.

**Fix:** Move the import inside `_is_row_attachment` (or wrap the top-level
import in a `try`/`except ImportError` that falls back to comparing against
the literal string `'ROW'` only), matching the lazy-import convention already
used for `smartsheet.models.sheet` / `smartsheet.models.folder`:

```python
def _is_row_attachment(att: Any) -> bool:
    parent_type = getattr(att, 'parent_type', None)
    if parent_type is None:
        return False
    try:
        from smartsheet.models.enums.attachment_parent_type import (
            AttachmentParentType,
        )
        if parent_type == AttachmentParentType.ROW:
            return True
    except Exception:
        pass
    return parent_type == 'ROW'
```
