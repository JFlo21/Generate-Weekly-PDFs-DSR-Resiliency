<objective>
Close the residual of G-11.1-4 (component b): make a D-11.1-01 registry-version
skip MISS cheap, so SC-1 holds whether or not the skip engages.

Purpose: on a skip hit discovery costs 44 s (run 33659869696, `Duration`
30.8 min, SC-1 met). On a miss it costs 3,214-4,999 s (runs 33634833356 /
33647771644, `Duration` 96.0 and 129.7 min, SC-1 missed) because
`_validate_single_sheet` downloads every row of every source sheet — 121
sheets x 26-41 s wall at 8 workers — while reading only `sheet.columns` and
`sheet.name`. The `include=` keyword on that call selects optional response
elements; it never restricted the row payload. The function's own sample
fallback (line 496) already issues a bounded three-row read that returns
columns, name AND rows — this plan issues that bounded read ONCE and reuses it,
deleting both the full download and the second round trip.

Expected effect: ~1-2 s/sheet on a miss instead of 26-41 s, i.e. a 0/121 run's
Phase 1 falls from 54-83 min to roughly 2-4 min, with SC-1 no longer hostage to
whether upstream recalcs moved every sheet's version since the last registry
write.

Output: a one-call, row-bounded validation read; the sample-row cache seeded
from it; three new tests (one behavioral, one negative-kwarg, one source pin);
one updated call-shape literal in the existing pin; a Living Ledger entry; an
owner-reviewed PR; and a post-merge canary reading of `⚡ Phase 1 complete` and
the Python `• Duration:` line.
</objective>

<sdk_facts>
Verified 2026-09-02 against the INSTALLED smartsheet-python-sdk (`4.3.0`, the
version this repo runs) plus the Smartsheet API `Sheet` object schema via
Context7 (`/websites/developers_smartsheet_api`). Do NOT re-derive these; do
NOT substitute a different call shape without re-verifying.

- `smartsheet.sheets.Sheets.get_sheet(sheet_id, include=None, exclude=None,
  row_ids=None, row_numbers=None, column_ids=None, page_size=None, page=None,
  if_version_after=None, level=None, rows_modified_since=None,
  filter_id=None)`. It issues `GET /sheets/{id}` and maps `row_numbers` to the
  `rowNumbers` query parameter.
- SDK docstring for `row_numbers`: "comma-separated list of Row numbers on
  which to filter the rows included in the result. Non-existent row numbers
  are ignored." It filters ROWS only.
- SDK docstring for `include` lists the valid optional elements: attachments,
  columnType, crossSheetReferences, discussions, filters, filterDefinitions,
  format, objectValue, ownerInfo, rowPermalink, rowWriterInfo, source, summary,
  writerInfo. Nothing in that list restricts rows — which is exactly why
  today's call is a full-sheet download (G-11.1-4 root cause).
- The API `Sheet` object always carries `name` and the `columns` array
  regardless of row filtering; `rows` is the filtered subset.
- `column_ids=` WOULD narrow the returned columns array. It is forbidden here
  (see prohibitions) — the mapping needs every column title on the sheet.
- Cost note: `row_numbers` does not change the request count. One request,
  one retry envelope, same 300 req/min budget, `PARALLEL_WORKERS_DISCOVERY`
  stays at 8.
</sdk_facts>
