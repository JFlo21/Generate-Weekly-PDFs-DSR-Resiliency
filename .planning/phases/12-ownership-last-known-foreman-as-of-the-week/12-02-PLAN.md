<objective>
Close the two Phase 11.1 review findings that Phase 12 owns, both in ownership code:
CR-01 (a false-positive sentinel classification that can delete a real person's Excel
attachment) and WR-01 (a fragile module-top-level Smartsheet enum import).

Purpose: CR-01 is a prerequisite for trusting the sentinel-superseded attachment cleanup
at the volume plan 12-06's remediation will produce — 93 WRs regenerating under real
names in one run is exactly the condition that turns a rare false positive into a real
data-loss event. WR-01 hardens the module that drives that same run.

Decisions this plan implements: **D-12-A** — this phase repairs the existing
`resolve_claimer` / `attribution_snapshot` read path rather than building a new
`wr_week_ownership` table, so the cleanup predicate on that path is the thing that must be
correct. OWN-02's core sentinel rule is already SHIPPED in PRs #375/#376/#377 — do NOT
re-implement `is_sentinel_claimer`, `freeze_row` or the cleanup gate; only these two
residuals remain.

Output: a narrowed `_is_sentinel_identifier`, a lazy `AttachmentParentType` import, and
regression tests pinning both.
</objective>
