<objective>
Build the OWN-03 claim-time attribution backfill script end to end, dry-run first,
against fixtures — the ladder that decides who owned each (WR, week, role) and the
report Juan approves before any live write.

Purpose: OWN-03 is the only genuinely new code surface in Phase 12. It repairs the
2026-08-24 defect (93 WRs / 5,824+ rows frozen as `Unknown Foreman`) by writing the
historically-correct claimer into the existing `billing_audit.attribution_snapshot`
rows that `resolve_claimer` already reads — so the next scheduled run regenerates the
files under real names with zero grouping-code change.

Decisions this plan implements:
- **D-12-A** — OWN-01's ladder is satisfied by `attribution_snapshot` + `resolve_claimer`
  plus the new `backfill_source` / `backfill_run_id` provenance columns. No
  `wr_week_ownership` table is built in Phase 12 (deferred to Phase 13). The ladder as
  implemented is `observed_in_week -> backfill_artifacts -> backfill_hash_history ->
  operator -> sentinel`. `REQUIREMENTS.md` OWN-01's `last_known_before_week` rung is
  STALE and is deliberately NOT implemented (decided OFF 2026-09-01 19:55).
- **D-12-B** — source 4 (`backfill_hash_history`) reads the Supabase hash store
  (`billing_audit.group_content_hash` + `pipeline_memory.group_state`), NOT a JSON file.
  There is no `--hash-history <path>` flag and no JSON fixture file.

Output: `scripts/backfill_claim_time_attribution.py`, its fixture-driven test suite, and
a `.gitignore` entry that keeps the PII-bearing report out of git.
</objective>
