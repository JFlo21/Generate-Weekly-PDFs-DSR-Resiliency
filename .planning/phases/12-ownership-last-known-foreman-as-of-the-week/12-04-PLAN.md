<objective>
Build OWN-03 source 5 — Smartsheet cell-history attribution — as a strictly isolated,
capped, off-hours job that names the rows sources 1-4 could not.

Purpose: source 5 is the only way to name rows from weeks before run memory whose artifact
filename is itself a sentinel or missing, and the only way to adjudicate the two-names-in-
one-week conflicts sources 3 and 4 must abstain on. It was DECIDED INCLUDED on 2026-09-02
00:35 — but only as a separate workflow with its own budget. Both scripts share one
Smartsheet API token and one 300 req/min ceiling, so running this inside
`generate_weekly_pdfs.py` would spend the production pipeline's budget (RESEARCH.md
Pitfall 5).

Decisions this plan implements: **D-12-B** — source 4 reads the Supabase hash store, so the
weeks it cannot reach (anything never seen in a run since 2026-05-25) fall through to
sources 3 and 5; that fall-through set is exactly this script's input. **D-12-A** — values
land in `attribution_snapshot` through the same owner-deployed RPC, tagged `operator`; no
new table.

The reference implementation for the paced fetch is `pipeline/snapshot_drift.py:371-438`.
`audit_billing_changes.py::_selective_cell_history_enrichment` is a STUB — it hardcodes
`history_meta["history_available"] = True` and never calls the API. Do not use it as a
model for anything but the selectivity idea.

Output: `scripts/backfill_cell_history_attribution.py`, its tests, and
`.github/workflows/cell-history-backfill.yml`.
</objective>
