table, the two provenance columns, and the `billing_audit.backfill_attribution(p_rows jsonb)`
RPC whose `WHERE` clause makes overwriting a real name impossible by construction — as a
reviewable `.sql` file Juan pastes into the Supabase SQL editor, plus the matching
contract-as-comment block in `billing_audit/schema.sql`.

Supabase, so the backfill cannot reuse it. Spec §4 option 1 was approved on 2026-09-02
00:35: a new owner-deployed RPC that enforces "sentinel or NULL only" server-side. This
repo does not and cannot apply Supabase schema changes itself — `billing_audit/schema.sql`
already establishes the contract-as-comment convention for exactly this situation.

Decisions this plan implements:
- **D-12-A** — no `wr_week_ownership` table is created. OWN-01's ladder is satisfied by
  `attribution_snapshot` + `resolve_claimer` plus the two new provenance columns

  any cross-week rung (decided OFF 2026-09-01 19:55).
- **D-12-B** — `backfill_hash_history` remains a valid provenance tag; its evidence source
  is the Supabase hash store, which needs no schema change here.

Output: `billing_audit/own03_backfill_attribution.sql`, an updated `billing_audit/schema.sql`,
a structural contract test, and Juan's confirmation that the SQL applied cleanly against
the live table.
