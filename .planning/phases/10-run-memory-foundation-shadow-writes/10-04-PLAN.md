SDK surface (smartsheet-python-sdk==4.3.0, exact-pinned by Phase 08 D-01; the
parameters below were confirmed present by introspecting the installed package):
  Sheets.get_sheet(sheet_id, ..., if_version_after=<int>, rows_modified_since=<ISO-8601>,
                   level=<int>, ...)
  Row model exposes a modified-at attribute and a version attribute.
  Documented behaviour (Smartsheet Get Sheet API reference): when ifVersionAfter
  matches the current version, the response is an ABBREVIATED Sheet object carrying
  only the version property. The response shape for rows_modified_since is NOT
  documented — establishing it empirically is observation T3's first job
  (10-RESEARCH.md Open Question 3).

CLI bootstrap convention to reuse — scripts/backfill_attribution_snapshot.py lines
1-70: module docstring documenting required env vars plus a runnable Usage line;
`_REPO_ROOT = Path(__file__).resolve().parent.parent` inserted into sys.path;
argparse with typed validators raising argparse.ArgumentTypeError on bad input.
Its BODY (Supabase writes, --week/--wr filters) is not a match — this script is
read-only against Smartsheet and writes only local JSON.

Test-fixture convention — tests/test_billing_audit_shadow.py: self-contained,
`unittest.mock` based, no tests/conftest.py exists in this repo. Per
10-RESEARCH.md's Package Legitimacy Audit no new package is introduced: D-08's
"vcrpy-style cassette" is satisfied by a hand-rolled JSON capture replayed through
mock objects, NOT by adding the vcrpy dependency.

Evidence the cassette must carry (10-DISCUSSION-LOG.md, the 12-item list):
  1  sandbox sheet ids, column structure, exact formula text, disposable label
  2  timestamped T0 / T1 / T2 / T3 sequence
  3  raw request parameters and raw response JSON for every probe
  4  whether the DEPENDENT sheet's version incremented after only the LOOKUP sheet
     was edited
  5  per-row modified-at diff, pre and post
  6  whether the affected row appears in the rows_modified_since set, and whether
     the value it carries is fresh or stale
  7  poll/retry timing, to separate "never updates" from "recalculation lag"
  8  exact SDK call signatures and pinned versions
  9  both scenarios recorded SEPARATELY: (a) the lookup value blanked/archived,
     (b) a mapping value edited in place
  10 SAFETY_WINDOW sensitivity: the same probe with and without the overlap watermark
  11 one explicit PASS/FAIL verdict sentence
  12 cassette path plus sheet ids, so the experiment is rerunnable

Formula-derived personnel columns for the passive half (10-CONTEXT.md discretion
note): foreman_observed, helper_observed, helper_dept, helper_job,
vac_crew_observed — the columns whose values come from cross-sheet lookups and
therefore change without a human touching the row.
