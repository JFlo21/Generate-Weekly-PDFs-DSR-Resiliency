<!-- Contracts the executor needs. Verified this session. -->

Excel output naming — generated_docs/WR_{wr}_WeekEnding_{MMDDYY}_{timestamp}{variant_suffix}_{hash}.xlsx,
with variant_suffix in {'', '_User_<foreman>', '_Helper_<foreman>', '_VacCrew'}.
The workflow's artifact organiser globs `WR_*_WeekEnding_*`. The embedded timestamp
means FILENAMES differ between two runs even when CONTENT is identical, so the
comparison must be over the multiset of file CONTENT hashes keyed by the stable
part of the identity, not over file names.

run_summary.json fields that legitimately differ between two runs and MUST be
excluded from the diff: `timestamp`, `duration_seconds`, `duration_minutes`.
Everything else in the frozen 21-key contract is billing-relevant and must match.
No memory counter was added to run_summary in this phase, so there is nothing
memory-specific to exclude (plans 10-01 through 10-03).

Existing comparison-script conventions to mirror — scripts/check_api_equality.py
(84 lines): compute set A, compute set B, diff, print a `FAIL: ...` line and return
non-zero on mismatch, print a `PASS: ...` line otherwise, `sys.exit(main())`.

scripts/run_6_gates.sh is NOT modified by this plan. Its Gate 6 runs TEST_MODE and
needs no credentials; adding a real-data gate would make the harness un-runnable in
CI and on a clean checkout. The comparison script is invoked separately.

Local-run semantics (.claude/skills/run-billing-pipeline-locally): SKIP_UPLOAD=true
runs the real Smartsheet fetch and real Excel generation but publishes nothing;
TEST_MODE=true takes the synthetic path and needs no token. Only SKIP_UPLOAD
exercises the shadow write path.

Run scoping for the comparison pair: WR_FILTER is applied at the GROUPING stage
(pipeline/grouping.py:1278), AFTER the fetch. Setting the SAME WR_FILTER on both
runs keeps the Excel output set small and deterministic while the memory write
phase still processes every fetched row — which is what success criterion 1
requires. MAX_GROUPS likewise bounds only the group loop.

Discovery caching: USE_DISCOVERY_CACHE with DISCOVERY_CACHE_TTL_MIN (default 7 days)
keeps the discovery phase cheap across the consecutive runs; do not clear
generated_docs/discovery_cache.json between them.

Hash-history safety: a SKIP_UPLOAD run must not advance change-detection state
(pipeline/orchestrate.py lines 2268-2280 document the contract). Back up
generated_docs/hash_history.json before the run sequence and restore it after, and
verify it is byte-identical at the end.
