  <action>Build the disposable Smartsheet formula rig and make the two triggering edits by hand, running Claude's probe commands between them</action>
  <instructions>
    Claude has built the read-only probe CLI (`scripts/mem04_experiment.py`) and its
    replay harness, and will run every command and parse every capture. What remains
    is the part Claude is not permitted to do: D-08 locks ZERO Smartsheet API writes
    for this phase, so the rig and both triggering edits must be made by hand in the
    Smartsheet UI. Creating the sheets or making the edits programmatically is exactly
    the behaviour that decision forbids, and the production guardrails treat
    Smartsheet writes as an approval-gated area.

    1. In a SANDBOX folder outside every production Resiliency folder, create two
       disposable sheets:
       - a LOOKUP sheet with a key column and a value column, holding a handful of
         rows;
       - a DEPENDENT sheet with a key column and a COLUMN FORMULA that resolves the
         value by cross-sheet INDEX/MATCH against the lookup sheet — the same shape
         the real `Foreman` / `Helper Dept #` lookups use.
       Put "DISPOSABLE TEST RIG — MEM-04" in both sheet names. Use invented data
       only: no real WR numbers, no real personnel names.
    2. Report both sheet ids and confirm `SMARTSHEET_API_TOKEN` is available in the
       shell Claude will run in.
    3. Then run this interleaved sequence, making each edit by hand between the two
       script invocations. Claude will give you the exact commands with your sheet
       ids substituted; the shape is:
       a. baseline capture, scenario `blank_lookup`
       b. BY HAND: blank / archive the looked-up value on the LOOKUP sheet. Note the
          cell, the old value, the new value and the exact time.
       c. probe capture, scenario `blank_lookup`
       d. baseline capture, scenario `edit_mapping`
       e. BY HAND: edit a mapping value in place on the LOOKUP sheet. Note the cell,
          the old value, the new value and the exact time.
       f. probe capture, scenario `edit_mapping`
    4. Paste back, for each scenario, the cell edited, the old and new values, and
       the edit time — these are evidence item 2 and cannot be recovered from the API.
  </instructions>
  <verification>

    and a `probe` section, the SDK version, both sheet ids, the disposable-test-rig

    target sheet or the subcontractor PPP sheet. A partial capture halts the next
    task rather than yielding a guessed verdict.
  </verification>
  <resume-signal>
    Reply with: both sandbox sheet ids, confirmation that the six steps ran, and the
    per-scenario edit details (cell, old value, new value, time). If a step failed,
    describe which one — a partial capture must be reported, not papered over.
  </resume-signal>
</task>
