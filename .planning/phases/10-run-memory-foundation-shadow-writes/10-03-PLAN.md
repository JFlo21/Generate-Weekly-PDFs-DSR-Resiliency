## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Upload worker threads -> the attachment side-channel dict | Concurrent writes from up to 8 workers |
| Post-upload flush -> `group_state` | A memory write sits alongside two production-critical flushes |
| Smartsheet attachment metadata -> memory | External identifiers enter the durable store |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-10 | Tampering | `_upload_one` side-channel capture inside the billing-guarded delete-then-upload worker | high | mitigate | Task 2 adds only a return-value read plus one lock-guarded dict write on the success branch, inside its own swallow-everything try/except; the worker's four status strings and the delete-before-attach order are asserted unchanged, and the two existing upload-contract test modules must pass unmodified. |
