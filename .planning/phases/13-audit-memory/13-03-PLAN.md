<objective>
Expand the proven tracer path from one check type to all three.

Purpose: 13-01 proved the architecture on `rate_sanity_mismatch`, the only check whose emitted
dict already carries D-01's declared identity fields. This plan adds the two checks whose
identity has to be reconstructed — `price_variance_anomaly` (no week scoping anywhere in the
check, so a WR's price pool routinely spans weeks) and `data_consistency_issue` (identity is a
set of literal message strings) — and makes the recipe mapping exhaustive so a future check type
cannot slip into production under a wrong key.

Output: a complete `build_finding_payloads`, the literal-string pin that protects every open
`data_consistency_issue` finding from a silent orphaning, and comment-only markers in
`audit_billing_changes.py` recording that the strings are now load-bearing.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Smartsheet cell values -> issue strings -> durable hash key | Operator-edited data decides which literal message strings enter a finding's identity |
| Source code message text -> durable identity contract | A cosmetic edit to a check's wording changes production identity semantics |
| `audit_results` dict -> key derivation | A finding of an unmapped or future check type reaches the dispatch |

## STRIDE Threat Register
