### Notes

- **Known deployment gap (not a code bug, per task scope):** `AUDIT_MEMORY_ENABLED`
  is defined in `pipeline/config.py:550-551` and fully wired in `orchestrate.py`, but
  is **not** present in `.github/workflows/weekly-excel-generation.yml`'s env block
  (grep for `AUDIT_MEMORY` in the workflow returns 0 hits vs. `HELPER2_ENABLED` at
  line 247 and `RUN_MEMORY_WRITE_ENABLED: '1'` at line 239). The feature is
  code-complete and self-gated fail-open/fail-closed, but cannot activate in
  production CI until a workflow var/secret is added. Flag this for the operator
  before assuming AUD-01..03 are "live" — they are dormant in the current deployed
  workflow.
- `RUN_MEMORY_INCREMENTAL_ENABLED` is also absent from the workflow env block by
  design (INC-04 requires default-OFF with a parity proof before flip) — comment at
  `.github/workflows/weekly-excel-generation.yml:234` documents this explicitly. Not
  a gap; matches the requirement.
- INC-02 is D-05 approved-partial per phase notes (no `11-VERIFICATION.md`): row_state
  decides group membership, and the scoped full re-fetch (PHASE 2b) supplies row
  content rather than trusting delta payload content directly. This is a documented
  design choice, not a wiring break — the affected-set → sheet-mapping →
  re-fetch → regen chain is intact end-to-end (see Flow 1 above).
- Python↔SQL contract check: `upsert_audit_findings` params are positional-by-name

  `upsert_rows_bulk`, `upsert_audit_findings`, `fetch_sheet_delta`,
