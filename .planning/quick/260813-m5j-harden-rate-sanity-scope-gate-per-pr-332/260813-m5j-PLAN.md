<objective>
Harden the rate-sanity current-cycle scope gate shipped in PR #332, closing the two
post-merge review findings without narrowing the detector's incident coverage.

- **F1 (Codex P1):** `_rate_sanity_in_scope` calls `_resolve_rate_recalc_cutoff_date`
  without `weekly_fallback_enabled`, so it defaults to `True` and applies the Weekly
  Reference Logged Date fallback even on sheets that map no Snapshot Date column at
  all. Production's own caller gates that fallback on
  `'Snapshot Date' in column_mapping` (pipeline/fetch.py:276, 389-402). Mirror it and
  fail closed.
- **F2 (Copilot — polarity corrected by research):** exclude `__is_subcontractor`
  rows. Their `Units Total Price` sits at the Subcontractor-Rates basis
  (`reduced_*_price`, or an in-place rescue overwrite at pipeline/fetch.py:472-481),
  not the New-Rates basis this detector compares against — a systematic ~12.6% false
  delta. The literal F2 ("restrict scope TO subcontractor rows") is REJECTED: the
  SAA-DE-20 incident sheet ("Resiliency Promax Database Backup 86", id
  1824542300262276) is one of the 110 non-subcontractor sheets, so that restriction
  would blind the detector to the exact defect class it exists for.

Purpose: keep the guardrail pointed at the real defect class while removing both
false-positive/false-negative holes the reviewers found.
Output: hardened scope gate + snapshot-column index helper + extended (never
replaced) out-of-scope counters + 10 regression tests + Living Ledger entry.

Report-only throughout: no row mutation, no writes to pricing / grouping / excel /
fetch / upload, no new env var, `RATE_SANITY_AUDIT_ENABLED` kill switch untouched.
</objective>
